# StatPro 전체 메뉴·화면 재구성 제안

## 목적과 적용 범위

제공된 화면은 DMAIC 입력 문서, 관리도 단계형 작업, 통계 방법 탐색 카드라는 세 가지
정보구조를 보여 준다. StatPro는 이를 참고하되 화면 배치·브랜드·아이콘·구독/잠금 정책을
복제하지 않는다. 이 문서는 현재 StatPro 엔진과 화면에서 확인된 기능만 `구현됨`으로
표시하며, 나머지는 `개발 예정` 또는 `외부 정책 필요`로 표시한다.

## 공통 화면 구성

1. **앱 셸**: 좌측 고정 메뉴, 본문 breadcrumb, 페이지 제목·목적, 우측의 결과/도움말
   행동으로 구성한다. 작은 화면에서는 메뉴를 drawer로 전환한다.
2. **작업공간**: 제목 아래에 단계 rail 또는 탭을 두고, 현재 단계/완료 조건/근거 연결을
   보여 준다. 탭은 긴 폼을 숨기기 위한 장식이 아니라 저장 단위와 검증 단위를 나타낸다.
3. **입력 문서**: 기본 정보는 먼저 열고, 부가 항목은 접힌 패널로 둔다. 필수 항목, 빈
   목록, 검증 오류, 저장되지 않은 수정, 최신 개정 아닌 연결을 분명히 표시한다.
4. **분석 실행**: `설정 → 데이터 입력 → 분석 실행 → 결과` 순서이다. 실행 전에는 입력
   검증·가정·제한을, 실행 후에는 ResultBundle·근거·원본 입력 digest를 표시한다.
5. **결과와 보고서**: 차트 또는 표, 핵심 수치, 신호/경고, 접근 가능한 대체 표, 다음 행동,
   내보내기를 같은 결과 맥락에 둔다. 내보내기 종류는 실제 생성 가능한 항목만 활성화한다.

## DMAIC 화면 구성

| 단계 | 주 화면 | 핵심 입력/연결 | 현재 상태 |
|---|---|---|---|
| 정의 | 프로젝트 헌장 | 범위, 지표, 팀, 위험; VOC·SIPOC·문제 정의·이해관계자 문서 | 개발 예정 |
| 측정 | 데이터 수집 계획 | 핵심 지표, 표본추출, 측정기·교정, 수집 양식, MSA/SPC/공정능력 Run | 개발 예정 |
| 분석 | 근본원인 작업공간 | 문제 범위, 가설, 잠재 원인, 원인 검증, 시정조치, DOE/통계 Run | 개발 예정 |
| 개선 | DOE 작업공간 연결 | 실험 설계, 반응, 최적화, 확인 실행 | 구현됨(기존 DOE 경로) |
| 관리 | 관리계획서·SPC 연결 | 관리 특성, SPC/MSA 실행 근거, 조치, FMEA 추적 | 구현됨(기존 FMEA/SPC 경로) |

### 측정: 데이터 수집 계획과 기준 성능

- 수집 계획은 `핵심 지표`, `기준값`, `목표값`, `문제/목표 정의`, 수집 전략, 표본추출,
  측정 시스템, 수집 양식, 수집자, 품질보증, 분석 방법, 비용/보고 형식으로 구성한다.
- 기준 성능은 공정·공정 책임자·평가 기간·지표 정의를 기록하고, 실제 공정능력·SPC·MSA
  판정은 완료된 Analysis Run의 ID·ETag·입력 digest를 참조한다. 계획 입력만으로 성능
  기준선이나 측정시스템 적합성이 확정되었다고 표시하지 않는다.

### 분석: 원인 탐색과 방법 선택

- `근본원인 분석` 문서는 문제/영향/범위, 분석 방법, 팀, 잠재 원인, 검증된 근본원인,
  시정조치, 결론을 관리한다.
- `특성요인도(이시카와)`는 범주·원인·근거를, `5 Why`는 문제에서 원인까지의 질문 사슬과
  각 근거를, `파레토 분석`은 항목·빈도/비용·기간·데이터 원천을 기록한다. DOE의
  효과 파레토와 일반 결함/원인 파레토는 다른 분석이며 같은 결과라고 취급하지 않는다.
- `분석 방법 선택`은 질문과 결과척도로 출발한다. 상관/회귀, t 검정, ANOVA, 비모수 검정,
  시계열, 일반 파레토는 현 엔진에 구현되지 않았으므로 카드에서 `개발 예정`으로 보인다.
  구현된 DOE·SPC·MSA만 실제 시작 행동을 제공한다.

### 개선: 실험 검증과 실행 가능한 개선안

- `개선안 선정 매트릭스`는 후보 개선안, 평가 기준, 기준별 가중치, 평가 점수, 근거,
  선정 사유를 분리해 기록한다. 총점은 입력 가중치와 점수의 계산 결과일 뿐, 최선의
  개선안을 자동으로 보증하지 않는다.
- `파일럿 계획`은 파일럿 유형, 대상 범위, 전/후 또는 비교 설계, 표본 크기, 기간,
  성공 지표, 중단 기준, 위험 대응을 기록하고 DOE·SPC·MSA·공정능력 실행을 참조한다.
  계획된 표본 수나 성공 기준은 파일럿 성공/승인 상태를 의미하지 않는다.
- `비용편익 분석`은 통화, 분석 기간, 비용/편익 항목, 발생 시점, 가정, 민감도 시나리오,
  계산된 재무 지표를 보관한다. 입력값에 기반한 의사결정 보조이며 재무 조언 또는 실제
  절감액 보장이 아니다.
- `실행계획`은 실행 전략, 단계, 책임자 참조, 소통 계획, 품질 계획, 교육 계획, 완료
  조건을 기록한다. 조직의 실제 권한·승인·교육 이수 여부는 외부 시스템의 근거 없이는
  확정 상태로 표시하지 않는다.

### 관리: 개선의 유지와 품질 신호

- `관리` 단계는 FMEA 관리계획서, 공정능력 분석, 통계적 공정관리(SPC)를 현재 기능으로
  연결한다. 이들은 각각 FMEA Study 또는 Analysis Run이 소유하므로 DMAIC 프로젝트에는
  ID·ETag·입력 digest 참조만 둔다.
- `DMAIC 관리 인계`는 관리 항목, 모니터링 계획, 반응 계획, 검토 일정, 연결 Run과
  근거를 보관하는 별도 revision 문서다. 같은 내용을 FMEA 관리계획서에 복제하지 않는다.
- `품질 관리 대시보드`는 지표 정의·데이터 원천·갱신 주기·마지막 갱신·경고 기준을
  명시하는 읽기 전용 집계 화면으로 계획한다. 데이터 원천 계약, 알림 수신자, 접근 권한이
  없는 상태에서 실시간 모니터링이나 경보 발송을 주장하지 않는다.
- `일반 결함 분석`은 결함 기회 정의, 분류 체계, 기간, 데이터 원천, 빈도/비용 지표를
  갖는 별도 문서로 계획한다. DOE 효과 파레토나 SPC 이상 신호와 동일한 분석으로
  취급하지 않는다.

## 접근성·신뢰성 규칙

- 상태는 `구현됨`, `개발 예정`, `외부 정책 필요`만 사용한다. 잠금·결제·크레딧 표시는
  사용하지 않는다.
- 단계, 탭, 접힌 패널, 표 추가/삭제는 키보드와 스크린리더 이름으로 조작 가능해야 한다.
- 사람/부서/후원자 입력은 로컬 문서의 참조값이며 실제 인사 권한 또는 전자승인을
  의미하지 않는다.
- 원인·가설·시정조치와 분석 결과는 서로 다른 소유 데이터다. 계산 결과는 ResultBundle
  을 재사용하고, DMAIC 문서는 ID·ETag·digest 참조만 보관한다.
