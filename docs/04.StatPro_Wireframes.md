## SCR-033 DOE 작업공간

```text
┌ 홈 > 실험계획법(DOE) > 실험명 ────────────────────────────────┐
│ 실험계획법(DOE)  [설계 중]             [도움말] [보고서]       │
├ [설계 및 계획] [실행 데이터] [분석] [결과] [최적화] [근거] ──┤
│ ① 실험 목적 ─ ② 인자·반응 ─ ③ 설계·블록 ─ ④ 실행표 ─ ⑤ 분석 │
├──────────────────────────────────────────────────────────────┤
│ 설계 유형 [완전요인 ▼]  [설계 상세 보기]                      │
│ 인자 설정: 이름 | 유형 | 낮은 수준 | 높은 수준 | 단위          │
│ 반응 설정: 이름 | 목표 | 규격 하한 | 규격 상한 | 기준          │
│ 실행 조건: 반복 | 무작위화 | 블록 | 중심점                    │
│ 완료 조건: 인자 2개 이상 · 반응 1개 이상                       │
│                                             [실행표 생성]     │
└──────────────────────────────────────────────────────────────┘
```

- `실행표 생성`은 화면당 유일한 primary action이다.
- 비활성 상태에는 누락된 인자·반응 조건을 바로 아래에 텍스트로 표시한다.
- 현재 설계 유형에는 완전요인, 일부요인, Plackett–Burman, 중앙합성,
  Box–Behnken을 표시한다. Taguchi 등 미구현 유형은 개발 예정 안내로 보낸다.
- 2026-10-28: `/doe`에 이 작업공간 셸을 구현했다. 각 설계 카드는 기존의
  검증된 설정 경로로 이동하며, 실행 데이터·분석·결과·최적화·근거 탭은 해당
  작업 단계와 가장 가까운 현재 기능으로 안내한다.

## SCR-034 SPC 작업공간

```text
┌ 통계적 공정관리(SPC) > 관리도 ─────────────────────────────────┐
│ ① 종류 선택 ───── ② 데이터 입력·검증 ───── ③ 분석 결과·출력    │
├ 관리도 카드: I-MR | Xbar-S | p/np/c/u | EWMA | CUSUM | Laney | G/T ┤
│ 선택한 관리도 설명 · 사용 조건 · 예시 · 전용 파라미터           │
├ 데이터 원본: 작업표 선택 | CSV | 직접 입력 | 표본 데이터        │
│ 완료 조건/검증 오류                                  [분석 실행] │
├ 결과: 관리 한계 칩 → 차트 → 접근 가능한 원본 표 → 이상 신호    │
│ 요약: CL/UCL/LCL/관리 한계 내 점 · 근거 · 경고 · 결과 출력      │
└────────────────────────────────────────────────────────────────┘
```

- I-MR, Xbar-S, p/np/c/u, EWMA, CUSUM, Laney P′/U′, G/T 및 경험적
  비정규 공정능력은 현재 선택 가능하다. G는 0 이상 정수인 사건 간 기회 수, T는 양수인
  사건 간 시간·거리·사용량을 입력한다.
- G/T 결과는 중앙값과 LPL/UPL 확률 한계, 차트, 접근 가능한 간격 표, 이상 신호 순서로
  표시한다. 기준선 평균을 비우면 1단계 기준선(Phase I)으로 현재 자료에서 모수를 추정하고,
  검증된 기준선 평균을 입력하면 2단계 감시(Phase II)로 전환한다. 결과는 기준선과 현재 입력
  평균을 함께 표시한다.
- 결과 출력은 SPC ResultBundle을 기준으로 한다. JSON 데이터는 현재 제공하고,
  PDF·Excel·PNG·SVG는 `개발 예정`으로 명시한다.

## SCR-036 DMAIC 정의 — 개발 예정

```text
┌ 개선 프로젝트(DMAIC) > 정의 ───────────────────────────────────────────┐
│ 프로젝트: [프로젝트 선택]  상태: 초안  [저장] [개정 이력]                │
├ 단계 탐색 ┬ 정의: 프로젝트 헌장 · VOC · SIPOC · 문제 정의 · 이해관계자 ──┤
│ 정의      │ ┌ 1. 프로젝트 정보 ───────────────────────────────────────┐ │
│ 측정      │ │ 제목* · ID · 프로젝트 책임자* · 후원자 · 챔피언 · 부서   │ │
│ 분석      │ │ 시작일 · 목표 종료일                                     │ │
│ 개선      │ └────────────────────────────────────────────────────────┘ │
│ 관리      │ ┌ 2. 사업 타당성 및 문제 정의 ────────────────────────────┐ │
│           │ ├ 3. 프로젝트 범위 [범위 내 n] [범위 외 n]                │
│           │ ├ 4. 성공 지표  ├ 5. 프로젝트 팀  ├ 6. 자원·예산          │
│           │ ├ 7. DMAIC 이정표 ├ 8. 이해관계자 ├ 9. 위험 등록부        │
│           │ └ 10. 가정 및 제약조건                                    │
├───────────┴────────────────────────────────────────────────────────────┤
│ [VOC 연결] [SIPOC 연결] [문제 정의 연결] [이해관계자 분석 연결]         │
│ 저장하지 않은 변경 또는 연결 문서의 최신 개정 상태를 명시               │
└────────────────────────────────────────────────────────────────────────┘
```

- 첫 화면은 프로젝트 정보만 열고, 나머지는 접힌 패널로 시작한다. 각 패널의
  숫자는 필수값 충족 또는 연결 항목 수를 나타내며 완료·승인 상태를 뜻하지 않는다.
- VOC는 수집 정보·데이터 지점·요구사항·불편·기회·조치·권고·다음 단계의
  접힌 섹션을 사용한다. SIPOC는 공정 경계와 Supplier/Input/Process/Output/Customer
  목록을 별도 표로 입력한다.
- 문제 정의는 문제·영향·현재-목표 격차·기간/범위·심각도/긴급도를 기록하고,
  이해관계자 분석은 영향력·관심도·태도·소통 계획·우려·기대를 기록한다.
- Word/PDF 내보내기, 샘플 양식 로드, 프로젝트 파일 열기는 구현 전까지 `개발 예정`
  안내로 표시한다. 저장이 구현되면 각 문서는 immutable revision과 digest를 가진다.

```text
│ 개선      │ │ 방법 · 주기 · 시작/종료일 · 데이터 원천                 │ │

│           │ ┌ 측정 시스템 ───────────────────────────────────────────┐ │

├───────────┴────────────────────────────────────────────────────────────┤
```

- 표본 수·오차한계·신뢰수준은 수집 계획의 입력값이며 통계적으로 유효한 표본
  설계를 자동 보증하지 않는다. 계산 기능을 제공할 때에는 입력 가정과 출처를 별도
  ResultBundle 또는 계획 근거로 남긴다.
- `교정 필요`, `MSA 필요`는 체크 항목이지 교정 완료·측정시스템 적합 판정이 아니다.
  MSA/Gage R&R, 공정능력, SPC는 새 데이터를 복제하지 않고 기존 실행 ID·digest를
  계획 개정본에 연결한다.

## SCR-038 DMAIC 분석 — 개발 예정

```text
┌ 개선 프로젝트(DMAIC) > 분석 > 근본원인 분석 ───────────────────────────┐
│ 프로젝트: [프로젝트 선택]  [저장] [개정 이력]                            │
├ 단계 탐색 ┬ 설정 · 잠재 원인 · 근본원인 · 시정조치 · 결론 ───────────────┤
│ 정의      │ 분석 정보: 제목* · ID* · 담당자* · 일자 · 공정/제품*         │
│ 측정      │ 문제·영향·범위 · 목표[]                                     │
│ 분석      │ 분석 방법: [특성요인도 + 5 Why] · 팀 규모 · 분석 기간         │
│ 개선      │ 잠재 원인[] → 근본원인[] → 시정조치[] → 결론                 │
│ 관리      │ [특성요인도 연결] [5 Why 연결] [파레토 연결] [DOE Run 연결]  │
├───────────┴────────────────────────────────────────────────────────────┤
│ 원인/가설은 검증된 원인이 아님을 표시 · 연결 Run의 digest/제한 사항 표시 │
└────────────────────────────────────────────────────────────────────────┘
```

- 특성요인도, 5 Why, 일반 파레토는 별도 문서이며 각 원인/항목에 근거 참조를
  연결한다. 일반 파레토는 DOE 효과 파레토를 재사용하지 않는다.
- 통계 방법 선택 화면은 질문·결과척도·자료 구조로 카드를 좁히며, 실제 구현된
  DOE/SPC/MSA 카드만 시작 행동을 제공한다. 나머지는 `개발 예정` 설명을 보인다.

```text
┌ 개선 프로젝트(DMAIC) > 개선 ──────────────────────────────────────────┐
│ 프로젝트: [프로젝트 선택]  [저장] [개정 이력]                            │
├ 단계 탐색 ┬ 개선: DOE · 개선안 선정 · 파일럿 · 비용편익 · 실행계획 ─────┤
│ 정의      │ [DOE 작업공간 열기]  분석 실행 근거[]                       │
│ 측정      │ ┌ 개선안 선정 매트릭스 ───────────────────────────────────┐ │
│ 분석      │ │ 평가 기준[] · 가중치 · 후보 개선안[] · 점수 · 선정 사유 │ │
│ 개선      │ └────────────────────────────────────────────────────────┘ │
│ 관리      │ 파일럿: 유형 · 범위 · 설계 · 표본 · 기간 · 성공/중단 기준  │
│           │ 비용편익: 통화 · 기간 · 비용[] · 편익[] · 가정 · 시나리오  │
│           │ 실행계획: 전략 · 단계[] · 소통 · 품질 · 교육 · 완료 조건   │
├───────────┴────────────────────────────────────────────────────────────┤
│ 계산 값/가정/근거를 함께 표시 · 승인/실제 효과는 외부 근거 없이는 미확정 │
└────────────────────────────────────────────────────────────────────────┘
```

- DOE는 기존 작업공간으로만 이동하고, 개선 프로젝트에는 Run ID·ETag·입력 digest를
  참조로 연결한다. DOE 결과·입력·보고서를 프로젝트 문서에 복제하지 않는다.
- 가중 점수, 파일럿 성공 지표, 비용편익 계산은 투명한 입력과 가정을 함께 제시한다.
  이러한 의사결정 보조 수치는 조직 승인, 재무 보증 또는 현장 적용 완료를 뜻하지 않는다.

```text
│ 분석      │ 모니터링 계획: 지표 정의 · 데이터 원천 계약 · 경고 기준      │
│ 개선      │ 품질 관리 대시보드: [개발 예정] · 일반 결함 분석: [개발 예정]│
│ 관리      │ 검토 일정 · 근거 Run ID/ETag/digest · 미확정 외부 승인       │
├───────────┴────────────────────────────────────────────────────────────┤
│ Run 결과를 복제하지 않음 · 지표 데이터 원천/수집 주기/갱신 시각 표시     │
└────────────────────────────────────────────────────────────────────────┘
```

- FMEA `ControlPlan`은 기존 FMEA 연구의 소유 데이터다. DMAIC 화면은 그 ID·개정·digest를
  참조할 뿐, 별도 관리계획서를 병렬로 만들지 않는다.
- SPC·공정능력은 완료된 Analysis Run으로 이동한다. 실시간 갱신, 경보 전송, 조직 승인과
  담당자 권한은 데이터 원천·통지 정책·IdP 근거가 제공될 때까지 `외부 정책 필요` 또는
  `개발 예정`으로 표시한다.

- 이 화면은 DOE·SPC·FMEA 계산을 중복 구현하지 않는다. 구현된 카드만 기존
  작업공간으로 이동하고, 나머지는 `개발 예정` 설명 패널로 연결한다.
- 단계 카드는 `목표`, `사용 가능한 도구`, `근거 연결 상태`, `다음 권장 행동`을
  텍스트와 아이콘으로 함께 표시한다. 상용 제품의 잠금·업셀 상태를 복제하지 않는다.

## SCR-020 워크시트

```text
┌ Header ─────────────────────────────────────────────────┐
├ Sidebar ┬ Filter/Transform Bar ─────────────────────────┤
│         │ Column profile: type · missing · min/max      │
│         ├───────────────────────────────────────────────┤
│         │ sticky columns | virtualized data table       │
│         │ numeric cells right aligned                   │
└─────────┴───────────────────────────────────────────────┘
```

- 열 선택 시 프로파일 drawer를 연다.
- 결측은 빈 문자열이나 0과 구분되는 전용 표시를 사용한다.

## SCR-041 FMEA 편집

```text
┌ Study / standard version / revision / approval ────────┐
│ Structure tree │ Function / Failure / Risk table       │
│                │ S | O | D | AP | owner | due | status │
│                ├───────────────────────────────────────┤
│                │ selected failure DetailDrawer         │
└────────────────────────────────────────────────────────┘
```

- 표준 버전 변경은 새 revision을 만든다.
- 위험은 색과 함께 텍스트·아이콘으로 표시한다.
- 승인 보고서는 인증 여부와 함께 `독립 승인 적용/미적용`, 이전 변경자 일치 판정을
  한 줄로 표시한다. 이 판정은 로컬 감사 actor 비교이며 기업 IdP 신원 검증을 뜻하지 않는다.

## SCR-060 개발 예정 안내

```text
┌ 기능명                                      [개발 예정] ───────┐
│ 이 기능은 아직 분석을 실행할 수 없습니다.                       │
│ 제공 예정 범위: …                                               │
│ 선행 조건: …                                                    │
│ 지금 사용할 수 있는 기능: [가까운 현재 기능으로 이동]           │

```

- 외부 AP 정책이나 기업 IdP처럼 고객 조직의 입력이 필수인 기능은
  `외부 정책 필요`를 표시하고, 지원되었다는 인상을 주지 않는다.
