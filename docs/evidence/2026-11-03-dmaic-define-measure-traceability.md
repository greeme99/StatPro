# DMAIC 정의–측정 근거 스냅샷 계약

## 관찰과 구현 판단

- **사용자 제공 업무 흐름:** 개선 프로젝트는 정의한 문제·범위·고객 요구를 바탕으로
  측정 기준과 분석 근거를 기록해야 한다.
- **구현 판단:** 측정 계획이 어떤 정의 문서를 근거로 작성됐는지는 저장 시점의
  문서 ID만으로 충분하지 않다. 각 문서의 개정과 digest를 함께 고정해야 후속 개정과
  혼동하지 않는다.
- 이 증분은 외부 DMAIC 제품이나 고객 데이터를 재사용하지 않는다.

## 구현된 계약

- `DmaicMeasurementPlan.source_documents`는 프로젝트에 연결된 최신 Define 문서의
  `document_type`, `document_id`, `revision`, `digest`를 불변 튜플로 보존한다.
- 저장 대상은 프로젝트 헌장, 고객의 소리(VOC), SIPOC 맵, 이해관계자 분석, 문제 정의다.
- 브라우저는 근거 문서 ID나 다이제스트를 전송하지 않는다. 서버의
  `save_measurement_plan`이 저장 직전 프로젝트 소유 참조에서 직접 스냅샷한다.
- 측정 계획 digest에는 이 스냅샷도 포함된다. 따라서 근거 문서 집합이 다른 계획 개정은
  서로 다른 식별값을 갖는다.

## 작업공간 표시

- `/home/dmaic/measure`는 저장 전 현재 정의 문서의 이름, 개정, digest 앞부분을 표시한다.
- 저장 완료 안내는 고정된 정의 문서 수와 분석 실행 근거 수를 함께 표시한다.
- 측정 계획 저장 API의 실제 응답은 프로젝트 개정이다. 프런트엔드는 이를 반영한 뒤
  측정 계획 조회 API로 저장 문서를 읽어 확인 안내에 사용한다.

## 검증과 제한

- 도메인 테스트는 프로젝트 헌장과 문제 정의를 저장한 뒤, 측정 계획이 동일한
  참조·개정·digest를 스냅샷하는지 검증한다.
- API 테스트는 정의 문서가 없는 프로젝트에서도 빈 근거 목록이 명시적으로 반환되는지
  검증한다.
- 이 증분은 정의 문서의 내용을 측정 계획에 복제하거나, 후속 정의 문서 개정 시 기존
  측정 계획을 자동 변경하지 않는다. 문서 간 차이 비교와 승인 워크플로는 후속 범위다.
