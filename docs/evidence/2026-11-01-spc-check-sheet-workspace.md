# SPC 체크 시트 작업공간 근거와 구현 경계

## 1. 입력 근거

사용자 제공 문서 `Ref.doc/핵심 도구 7가지와 실제 활용 사례.pdf`는 체크 시트를
현장에서 결함·사건을 정해진 분류로 빠르게 기록하고 빈도를 집계하는 품질 도구로 설명한다.
이 문서는 StatPro의 업무 흐름과 정보구조를 설계하는 참조 자료로 사용했다.

이 자료는 Minitab 14의 계산식, 기본값, 명령, 파일 형식 또는 런타임 동작을 증명하지 않는다.
따라서 이 증분은 Minitab 동등성 증거가 아니라 공개 가능한 일반 품질 도구 개념을 바탕으로 한
StatPro 독립 구현이다.

## 2. 구현한 수직 증분

- 전용 경로: `/spc/tools/check-sheet`
- 작업 흐름: `체크 시트 정의 → 현장 발생 기록 → 빈도·비율 확인 → 파레토 분석으로 인계`
- 문서 모델: 체크 시트와 기록을 불변 스냅샷으로 보존하고 변경마다 revision과 digest를 갱신한다.
- 동시성: 저장소 storage version을 사용한 낙관적 잠금으로 오래된 화면의 덮어쓰기를 거부한다.
- 분석 결과: 공통 `ResultBundle` 경계로 총 발생 수, 분류 수, 분류별 빈도·비율 및
  파레토 입력용 데이터를 반환한다.
- API: 생성, 조회, 기록 추가를 각각 분리하고 ETag와 저장 버전을 응답한다.
- 화면: 공정·분류 기준 정의, 위치·교대·LOT·메모를 포함한 기록 입력, 실시간 요약과
  원시 기록 표를 한 작업공간에서 제공한다.

## 3. 검증

- `.venv\Scripts\python.exe -m unittest tests.test_check_sheet tests.test_api`
  - 27개 테스트 통과
- `npm test -- --run`
  - 3개 테스트 파일, 74개 테스트 통과
- `npm run build`
  - TypeScript와 Vite 프로덕션 빌드 통과
- `uvx ruff check ...`
  - 새 체크 시트 파일의 import 정렬 문제를 수정했다.
  - 전체 저장소에는 이 증분과 무관한 기존 Ruff 오류 7건이 남아 있어 변경 파일 단위 검증과
    전체 오류 목록을 구분해 관리한다.

## 4. 남은 범위

- CSV·Excel 가져오기와 체크 시트 표준 양식 내보내기
- 사용자·교대별 권한과 전자 서명
- 일반 파레토 차트의 저장 모델·분석 실행·보고서 구현
- 체크 시트 분류 마스터와 FMEA 결함 모드의 ID 기반 연결
