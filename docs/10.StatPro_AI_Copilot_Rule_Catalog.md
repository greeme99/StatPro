# StatPro AI Copilot 현장 Rule Catalog

## 목적과 작동 경계

AI Copilot은 제조·품질 현장에서 관찰된 상황을 분석 실행으로 단정하지 않는다. 검토된 Rule을 먼저 적용하여 `현장 상황 → 권장 작업공간 → 메뉴 경로 → 입력 점검표 → 업무 절차`를 안내한다. Rule이 일치하지 않을 때만 조직이 명시적으로 설정한 Gemini 2.5 Flash 보완 응답을 사용한다.

모든 Rule은 사용자의 데이터, 분석 설정, FMEA 문서 또는 승인 상태를 자동으로 변경하지 않는다. 계산·승인·내보내기는 해당 작업공간에서 사용자가 검토하고 실행한다.

## 판정 우선순위

1. 고정 고위험·고의도 Rule: 수율 최적화 DOE, 설비 비가동 DMAIC, Xbar-R Nelson 규칙 초안
2. 현장 Rule Catalog: 제품 기능별 상황과 작업 절차
3. 공통 선택 안내: 목적·데이터형·수집 구조 확인
4. 미일치: 로컬 한계를 알리고, 명시적 Gemini 설정이 있을 때만 보완 응답

## 산업계 비즈니스 케이스 확장

사용자 제공 산업계 사례 문서 1·2·4·5·6·7의 전자제조 흐름을 반영해 다음 Rule을 추가했다.

| 상황 | Rule ID | 기본 진입 | 사업영향이 명확할 때 |
|---|---|---|---|
| SMT 납땜·툼스톤·브리지 | `case-smt-solder-defect` | DMAIC·DOE·SPC | 수율·재작업 손실을 DMAIC 프로젝트로 승격 |
| AOI·ICT·FCT 오탐/미탐 | `case-aoi-measurement`, `case-functional-test-yield` | MSA·Measure | 출하·고객 영향이면 DMAIC로 승격 |
| 리플로우·SPI·배치 편차 | `case-reflow-optimization`, `case-paste-printing`, `case-placement-accuracy` | DOE 또는 SPC | FPY·PPM·스크랩 영향이면 DMAIC로 승격 |
| PCB·공급사·조립 변동 | `case-pcb-process-variation`, `case-supplier-variation`, `case-assembly-fastening` | SPC·FMEA·Control Plan | 반복 불량·안전·비용 영향이면 DMAIC로 승격 |
| 신규 제품·반도체 공정 | `case-dfss-new-product`, `case-semiconductor-drift` | DFSS/DMADV 또는 SPC | 양산 수율·lot 격리 영향이면 프로젝트화 |
| 출하·현장 고장·CAPA | `case-customer-complaint`, `case-field-capa` | DMAIC·FMEA·CAPA 안내 | 반복·보증·고객 영향이면 DMAIC 유지·확대 |
| FMEA 예방·탐지 조치 | `fmea-prevention-detection-action` | FMEA 조치·검토·승인 | AP가 높으면 예방·탐지 개선 또는 근거 문서화 |
| 수율·재무 KPI 개선 | `dmaic-yield-optimization` | DMAIC 프로젝트 개요 | FPY·RTY·Scrap·Rework·DPMO·Cpk의 사업영향이 명확하면 DMAIC 승격 |
| 공차·분포 강건성 | `doe-monte-carlo-robustness` | DOE 반응표면 및 최적화 | 시뮬레이션 결과를 Pilot Run으로 검증 |
| 리플로우 프로파일·BGA Void | `doe-reflow-profile-void` | DOE 실험 설정 | 제품·페이스트·장비별 기준과 적용판 확인 |
| SPC 신호·반응계획 | `spc-rule-response-plan` | SPC 관리도 결과·반응계획 | Western Electric/Nelson 규칙과 CAPA 연결 |
| High AP 조치 근거 | `fmea-high-ap-evidence` | FMEA 조치·검토·승인 | 예방·탐지 개선 또는 현행관리 타당성 근거 기록 |

이 확장은 단일 도구를 즉시 실행하는 자동화가 아니라, 현상에서 시작해 `Workspace → Workflow → 분석 → 결과 활용`으로 연결하는 Rule-first 안내다. DMAIC 승격은 사업영향이 명확할 때 사용자 승인으로 제안한다. DMADV/DFSS, Attribute MSA, 8D/CAPA, FDC/APC/R2R, PPAP는 현재 Rulebase에서 선행조건과 외부 정책 필요성을 설명하며, 완전한 실행 엔진은 후속 개발 항목으로 관리한다. 상세 근거와 관찰·제안·미확인 구분은 `docs/evidence/2026-11-07-industrial-business-case-catalog-4-6.md`에 보존한다.

## 범위 밖 비즈니스 케이스 처리

사용자가 현재 StatPro에서 실행할 수 없는 업무(예: MES/ERP 운영, FDC·APC·R2R 폐루프 제어, PPAP·8D/CAPA 실행, DFSS/DMADV 전용 설계, 임상·의료통계)를 질문하면 Copilot은 StatPro 기능으로 가장하지 않는다. 응답에 `StatPro 제공 범위 밖`을 명시하고, 적합한 전문 도구와 필요한 연계 요구사항(권한, 데이터 형식, 승인·감사 계약)을 제안한다. 이 경우 `unmatched`로 표시되며 자동 계산·승인·제어를 실행하지 않는다.

고정 Rule까지 포함한 정확한 실행 목록은 `GET /v1/copilot/rules`에서 제공한다. API 응답은 UI가 작업공간 링크, 메뉴 경로, 점검표, 업무 절차를 직접 표시할 수 있는 계약이다.

## Rule 정의 계약

각 Rule은 다음 값을 반드시 갖는다.

| 필드 | 용도 |
|---|---|
| `rule_id` | 변경 추적 가능한 고유 식별자 |
| `domain`, `situation` | 사용자가 이해할 수 있는 현장 맥락 |
| `trigger_groups` | 모든 그룹에서 하나 이상이 충족되는 결정적 조건 |
| `recommended_tool`, `menu_path`, `action` | 권장 도구와 이동 경로 |
| `checklist`, `workflow_steps` | 분석 전에 확인할 항목과 실제 업무 절차 |
| `source_reference` | 제품 계약 또는 검증 근거 문서 |

새 기능을 추가할 때는 화면의 키워드만 추가하지 않는다. 먼저 해당 기능의 입력 계약과 결과 근거를 문서화하고, 현장 상황·금지/선행조건·작업 흐름·소스 근거가 갖춰진 Rule을 카탈로그에 추가한다.

## 외부 생성형 AI 경계

Gemini는 Rule에 없는 질문을 보완하는 선택적 기능이다. `STATPRO_COPILOT_LLM_ENABLED=true`와 `GEMINI_API_KEY`가 모두 있는 로컬 환경에서만 호출한다. API 키는 `.env`에만 저장하며 응답, 로그, 보고서 또는 Git에 포함하지 않는다. Gemini 응답도 안내일 뿐 통계적 판단·기업 정책 승인·전자서명을 대체하지 않는다.
