# StatPro AI Copilot 현장 Rule Catalog

> 최신 기준일: 2026-11-08. 이 카탈로그는 Rulebase 우선 응답의 현재 범위를 기록한다. 규칙 미일치 시에만 명시 활성화한 Gemini → Ollama 폴백을 시도하며, 실제 외부·로컬 모델 연결 여부는 사용자 환경 설정과 별도 검증 결과에 따른다.

## 목적과 작동 경계

AI Copilot은 제조·품질 현장에서 관찰된 상황을 분석 실행으로 단정하지 않는다. 검토된 Rule을 먼저 적용하여 `현장 상황 → 권장 작업공간 → 메뉴 경로 → 입력 점검표 → 업무 절차`를 안내한다. Rule이 일치하지 않을 때만 조직이 명시적으로 설정한 생성형 AI 보완 응답을 사용한다.

모든 Rule은 사용자의 데이터, 분석 설정, FMEA 문서 또는 승인 상태를 자동으로 변경하지 않는다. 계산·승인·내보내기는 해당 작업공간에서 사용자가 검토하고 실행한다.

## 판정 우선순위

1. 고정 고위험·고의도 Rule: 수율 최적화 DOE, 설비 비가동 DMAIC, Xbar-R Nelson 규칙 초안
2. 현장 Rule Catalog: 제품 기능별 상황과 작업 절차
3. 공통 선택 안내: 목적·데이터형·수집 구조 확인
4. 미일치: 요청 난이도를 분류해 단순 요청은 Gemini 3.5 Flash-Lite, 복잡·다단계·코드 요청은 Gemini 3.8 Flash에 보냄
5. Gemini 실패 또는 비활성화: loopback Ollama의 일반 Workflow 모델 또는 코드 모델로 한 번 보완
6. 모든 폴백 실패: 재시도 및 분석 목표·데이터 구조·현장 제약의 수동 입력 안내

이 확장은 단일 도구를 즉시 실행하는 자동화가 아니라, 현상에서 시작해 `Workspace → Workflow → 분석 → 결과 활용`으로 연결하는 Rule-first 안내다. DMAIC 승격은 사업영향이 명확할 때 사용자 승인으로 제안한다. DMADV/DFSS, Attribute MSA, 8D/CAPA, FDC/APC/R2R, PPAP는 현재 Rulebase에서 선행조건과 외부 정책 필요성을 설명하며, 완전한 실행 엔진은 후속 개발 항목으로 관리한다. 상세 근거와 관찰·제안·미확인 구분은 `docs/evidence/2026-11-07-industrial-business-case-catalog-4-6.md`에 보존한다.

## 범위 밖 비즈니스 케이스 처리

사용자가 현재 StatPro에서 실행할 수 없는 업무(예: MES/ERP 운영, FDC·APC·R2R 폐루프 제어, PPAP·8D/CAPA 실행, DFSS/DMADV 전용 설계, 임상·의료통계)를 질문하면 Copilot은 StatPro 기능으로 가장하지 않는다. 응답에 `StatPro 제공 범위 밖`을 명시하고, 적합한 전문 도구와 필요한 연계 요구사항(권한, 데이터 형식, 승인·감사 계약)을 제안한다. 이 경우 `unmatched`로 표시되며 자동 계산·승인·제어를 실행하지 않는다.

고정 Rule까지 포함한 정확한 실행 목록은 `GET /v1/copilot/rules`에서 제공한다. API 응답은 UI가 작업공간 링크, 메뉴 경로, 점검표, 업무 절차를 직접 표시할 수 있는 계약이다.

카탈로그 소비자는 `domain`, `q`, `limit` 쿼리로 현재 작업공간에 필요한 규칙만 조회할 수 있다. `q`는 Rule ID·영역·상황·권장 도구·메뉴 경로를 검색하며, `limit`은 1~200으로 제한된다. Copilot, 교육 화면, 관리자 검토 화면은 동일한 서버 계약을 사용해야 한다.

## Rule 정의 계약

각 Rule은 다음 값을 반드시 갖는다.

| 필드 | 용도 |
|---|---|
| `rule_id` | 변경 추적 가능한 고유 식별자 |
| `domain`, `situation` | 사용자가 이해할 수 있는 현장 맥락 |
| `trigger_groups` | 모든 그룹에서 하나 이상이 충족되는 결정적 조건 |
| `recommended_tool`, `menu_path`, `action` | 권장 도구와 이동 경로 |
| `checklist`, `workflow_steps` | 분석 전에 확인할 항목과 실제 업무 절차 |
| `source_reference` | 제품 계약 또는 검증 근거 문서 |

새 기능을 추가할 때는 화면의 키워드만 추가하지 않는다. 먼저 해당 기능의 입력 계약과 결과 근거를 문서화하고, 현장 상황·금지/선행조건·작업 흐름·소스 근거가 갖춰진 Rule을 카탈로그에 추가한다.

## 외부 생성형 AI 경계

Gemini는 Rule에 없는 질문을 보완하는 선택적 기능이다. `STATPRO_COPILOT_LLM_ENABLED=true`와 `GEMINI_API_KEY`가 모두 있는 로컬 환경에서만 호출한다. 단순 요청은 `STATPRO_COPILOT_GEMINI_SIMPLE_MODEL`(기본 `gemini-3.5-flash-lite`), 복잡·다단계·코드 요청은 `STATPRO_COPILOT_GEMINI_COMPLEX_MODEL`(기본 `gemini-3.8-flash`)로 분기한다. API 키는 `.env`에만 저장하며 응답, 로그, 보고서 또는 Git에 포함하지 않는다. Gemini 응답도 안내일 뿐 통계적 판단·기업 정책 승인·전자서명을 대체하지 않는다.

Ollama 로컬 모델은 OpenAI 호환 `chat/completions` endpoint를 사용하는 Gemini 다음 폴백 경로다. `STATPRO_COPILOT_OLLAMA_ENABLED=true`, `STATPRO_COPILOT_OLLAMA_URL`이 있어야 하며 URL은 `127.0.0.1`·`localhost`·`::1` loopback HTTP만 허용한다. 일반 Workflow에는 `STATPRO_COPILOT_OLLAMA_WORKFLOW_MODEL`(기본 `qwen3:4b-q4_K_M`), 코드 생성에는 `STATPRO_COPILOT_OLLAMA_CODE_MODEL`(기본 `qwen2.5-coder:7b-instruct-q4_K_M`)을 사용한다. 기존 `STATPRO_COPILOT_LOCAL_LLM_*` 키는 호환 목적으로 지원한다. 각 공급자의 원시 응답 구조와 답변·권장 도구·메뉴 경로·체크리스트·업무절차 JSON 계약은 공급자 경계에서 검증한다. Gemini의 네트워크·구조·파싱·계약 오류는 Ollama로 넘기고, Ollama까지 실패한 경우에만 재시도 및 수동 입력 안내로 실패 폐쇄한다.

`GET /v1/copilot/status`는 Rulebase→Gemini→Ollama→수동 입력 경로의 **비밀값 없는 설정 증거**를 제공한다. Rule 수, Gemini 활성화·자격증명 존재 여부·선택 모델명, Ollama 활성화·loopback endpoint 유효성·선택 모델명과 수동 입력 가능 여부만 반환하며 API 키·endpoint 원문·사용자 대화는 반환하지 않는다. 이 조회는 모델을 호출하지 않으므로 `live_verified=false`는 연결 실패를 뜻하지 않고, 실제 Gemini/Ollama 실행 검증이 아직 수행되지 않았음을 뜻한다.

## Text to Workflow 대화 흐름

Copilot 패널은 최근 사용자 질문과 Workflow가 있는 안내를 같은 브라우저 메모리에 유지한다. 다음 질문에는 최근 6개 항목을 최대 1,200자로 정리해 현재 저장 근거와 합쳐 최대 1,800자로 전달하며, 사용자는 `대화 초기화`로 즉시 지울 수 있다. 최신 안내의 권장 도구·단계별 Workflow·작업공간 링크는 대화 상단에 고정한다. 이 대화 문맥은 Rulebase가 일치한 질문의 외부 전송을 유발하지 않는다. 사용자가 Gemini 또는 Local LLM 폴백을 명시적으로 활성화한 뒤에도 Rulebase와 일치하지 않는 질문에 한해 해당 공급자에게 전달될 수 있으므로, 조직의 데이터 전송 정책을 확인해야 한다.
