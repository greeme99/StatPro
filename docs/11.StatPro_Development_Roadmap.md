# StatPro 개발 로드맵 및 완료 기준

> 기준일: 2026-11-18. 이 문서는 로컬 제품의 실제 구현, 자동 검증, 배포 검사를 분리해 기록한다. 제품 요구사항은 `01.StatPro_SRS.md`, 기능 계약은 `02.StatPro_PRD_FS.md`, 화면과 경로는 `03.StatPro_IA.md`를 따른다.

## 1. 현재 기준선

StatPro는 로컬 우선 제조·품질 분석 제품으로, 홈에서 작업공간을 열고 `설정 → 데이터 → 분석 → 결과 → 보고서` 순서의 Workflow를 따른다. 분석 결과는 `ResultBundle` 경계를 통해 입력 digest, 엔진 버전, 경고와 공개 근거를 보존한다.

| 영역 | 현재 제공 범위 | 검증 상태 |
| --- | --- | --- |
| DOE | 완전·부분·분할구 요인설계, 반응표면, Plackett-Burman, 최적화, HTML/PDF/XLSX/ZIP·SVG 보고서 | Python 계약 테스트 및 Windows PDF 회귀 검사 |
| SPC·공정능력 | I-MR, Xbar-R/S, EWMA, CUSUM, p/np/c/u, Laney P′/U′, G/T, 정규·경험적 비정규 능력 | 엔진·API·결과 계약 테스트 |
| MSA | 교차·중첩·불균형 REML Gage R&R, 편의·선형성, 속성 일치도, 다중 형식 보고서 | 엔진·보고서 계약 테스트 |
| FMEA | PFMEA, 공정 흐름·관리계획서 추적, 로컬 직무분리·재인증 승인·감사 이력 | 로컬 정책과 API 계약 테스트 |
| DMAIC | Define~Control 불변 개정, DOE/SPC/MSA/FMEA 근거 연결, DOCX/PDF 종합 보고서 | 문서·연결 계약 테스트 |
| AI Copilot | Rulebase·사용자 규칙 우선, EXAONE 2.5 → 읽기 전용 Codex SDK → 수동 입력 폴백 | 단위·API 계약 테스트, 실제 모델 응답은 별도 운영 검증 |
| 기초 추론·회귀 | Jarque–Bera 정규성 진단, 독립표본 Welch t-검정, 일원 분산분석, 다중 예측변수 OLS, 계수·ANOVA·잔차·leverage 결과, OLS 잔차–적합값 PNG/SVG·인쇄 투영 | 코어·OpenAPI 경로·웹 입력/결과 계약 테스트 |

2026-11-18에는 Windows Chromium에서 GPU 초기화가 PDF 생성을 중단하던 DOE 보고서 오류를 수정했다. 렌더러는 임시 브라우저 프로필과 `--disable-software-rasterizer`를 사용하며 `--no-sandbox`를 사용하지 않는다.

## 3. 다음 우선순위

### P0 품질 게이트 자동화

`advanced`와 `codex` optional 그룹의 직접 의존성은 라이선스 근거와 함께 정책·SBOM에 등록했고 `oss_gate --check`를 통과했다. 변경 검증은 로컬에서 Python 전체 테스트, 웹 검사, OSS 게이트를 실행한 뒤 Conventional Commit으로 기록하고 `origin`에 push한다. Vercel Preview 검사는 배포 성공만 확인하므로 통계 계산·API 계약의 대체 검증이 아니다.

**완료 조건**: 변경마다 `unittest discover`, `npm run check`, `oss_gate --check`를 로컬에서 실행하고, 검증 결과를 커밋 메시지 또는 개발 문서에 기록한 뒤 `origin`에 push한다.

### P1 분석 선택 도우미의 통계 방법 확장

Jarque–Bera 정규성 진단, 다중 예측변수 OLS, 독립·대응표본 t-검정, 일원 분산분석의 코어·API·작업공간·결과 투영은 완료했다. 다음 우선순위는 범주형 연관성, 비모수 검정과 다항·로지스틱 회귀다. 회귀와 추론 결과 차트는 ResultBundle에 엔진 산출 표 또는 plot 데이터가 명시적으로 있을 때만 제공하며, UI가 원본 입력에서 차트를 재계산하지 않는다.

**완료 조건**: 각 방법은 입력 계약, 오류·가정 표시, 공개 근거, ResultBundle, API·작업공간·대체 표, 독립 기준 벡터 테스트를 모두 갖춘다.

### P2 데이터 원천과 작업표 확장

Parquet/SQL 가져오기, 다중 시트 선택, 조인과 제한된 재현 가능 변환을 추가한다. 임의 코드 실행이나 출처가 불명확한 자동 변환은 포함하지 않는다.

**완료 조건**: 원본·변환 digest, revision, 타입·결측 검증, 가져오기 실패 원인과 CSV 내보내기 호환성이 보존된다.

### P3 SPC 고급 감시와 운영 연결

부분군/one-sided EWMA, ARL 설계, stage 관리와 실시간 수집 연결은 독립 증분으로 다룬다. 현재 결과를 실시간 모니터링 또는 자동 경보로 해석하지 않는다.

**완료 조건**: 기준선 수립과 감시 단계가 분리되고, 입력 시간 기준·지연·재시도·권한·경보 정책이 명시된 경우에만 외부 연동을 활성화한다.

### P4 FMEA 기업 통합

실제 IdP, MFA, 계정 수명주기, 전자 승인 정책은 제공된 조직 정책과 운영 검증을 전제로 한다. 로컬 actor 문자열 비교와 재인증은 IdP 신원 보증이 아니다.

**완료 조건**: 테넌트 정보, 역할 매핑, 직무분리 정책, 감사 보존·철회·장애 절차와 운영 검증 증거가 제공되고 보안 검토가 승인된다.

## 4. 검증 및 배포 기준

| 단계 | 필수 확인 | 현재 기준 |
| --- | --- | --- |
| 코어·API | `python -m unittest discover -s tests` | 2026-11-18 통과 |
| 웹 | `cd web; npm run check` | 2026-11-18 통과 |
| 공급망 | `python tools/oss_gate.py --check` | 2026-11-18 통과: advanced·openai-codex 정책/SBOM 동기화 |
| 배포 | PR의 Vercel Preview 상태와 대상 commit SHA 확인 | `aca227c` Preview READY |

실제 EXAONE·Codex SDK 질의, 실제 IdP/MFA, 원격 데이터 수집, 전자서명 규제 적합성은 자동 테스트 통과만으로 검증되었다고 주장하지 않는다. 각 항목은 조직의 자격증명, 비용·전송 정책, 운영 환경과 별도 승인 증거가 필요하다.

## 5. 문서 유지 규칙

기능 변경은 같은 변경에서 SRS, PRD/FS, IA, 테스트 결과 및 이 로드맵의 상태를 함께 갱신한다. 완료 표시는 코드·API·UI·테스트·근거가 모두 확인된 경우에만 사용한다. 외부 정책 또는 운영 증거가 필요한 기능은 `외부 정책 필요`로 유지한다.
