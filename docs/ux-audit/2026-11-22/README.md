# StatPro UI/UX 2차 개선 감사

## 범위와 방법

- 기준 경로: `홈 → 작업표 및 데이터 → 분석 선택 → 결과 및 보고서`
- 화면 조건: Edge headless, 1440×1000, 라이트 테마, 한국어, 모션 감소
- 증거: 화면 PNG와 브라우저 접근성 트리
- 디자인 기준: 프로젝트 `DESIGN.md`와 Work App Design System v1.0
- 자동 접근성 검사: `@axe-core/playwright`로 핵심 4개 화면의 WCAG 2.1 A/AA를 검사

## 발견 사항과 개선 제안

| 우선순위 | 화면 | 문제와 영향 | 제안 | 상태 |
|---|---|---|---|---|
| P0 | 결과 및 보고서 | `분석 실행 결과` 카드가 `/`로 이동해 인증된 작업 흐름을 벗어남 | 최근 실행을 제공하는 `/dashboard`로 연결 | 반영 |
| P1 | 결과 및 보고서 | 구현된 카드의 제공 상태가 보이지 않고 모든 행동이 `기능으로 이동`으로 동일함 | `구현됨` 배지와 목적별 행동 문구 제공 | 반영 |

| P1 | 결과 및 보고서 | 다른 주요 화면과 달리 현재 위치 경로가 없음 | `홈 → 결과 및 보고서` 경로 추가 | 반영 |

| P2 | 공통 셸 | 1440px 화면에서 기본 360px 사이드바가 작업 영역의 25%를 점유함 | 실제 사용자 과업 테스트 후 기본 폭 축소 여부 결정 | 보류 |

## 반영 내용

- 보고서 카탈로그의 잘못된 분석 결과 링크를 `/dashboard`로 교정
- 구현된 모든 카탈로그 카드에 텍스트 상태 배지와 아이콘 표시
- 보고서 카드 행동을 `최근 분석 실행 보기`, `DOE 보고서 만들기` 등으로 구체화
- 카탈로그에 경로 탐색 추가
- 작업표 목록·빈 상태·가져오기·상세 화면 용어를 `작업표`로 통일
- 핵심 4개 화면에 Playwright + axe 자동 회귀 검사를 추가하고 `serious`·`critical` 위반을 차단
- 로컬 문서 저장소와 무관하게 재현되도록 검사 중 API 응답을 고정

## 검증

- 변경 관련 Vitest: 6건 통과
- TypeScript + Vite 프로덕션 빌드: 통과
- 개선 후 브라우저 캡처: 2개 화면, 페이지 오류 0건
- 자동 WCAG 회귀: `npm run test:a11y`로 실행하며 상세 axe 결과와 실패 trace를 산출
- 표준 `npm run check`의 마지막 단계에서도 WCAG 회귀 검사를 실행
- 전체 `App.test.tsx` 1차 실행: 138건 중 134건 통과. 직접 관련 실패 2건은 수정·선별 재검증했고, 별도 분석·조인 흐름 2건은 후속 확인 대상

## WCAG 회귀 기준선

자동 검사는 WCAG 2.1 A/AA의 `serious`·`critical` 위반을 대상으로 한다. 최초 도입 시점의 기존 위반은 화면·규칙별 대상 수로 명시하고, 새로운 규칙 위반 또는 대상 수 증가를 회귀로 처리한다. axe 전체 결과는 각 Playwright 테스트에 JSON으로 첨부된다.

| 화면 | `aria-allowed-attr` | `color-contrast` | `label-content-name-mismatch` |
|---|---:|---:|---:|
| `/home` | 1 | 11 | 1 |
| `/data` | 1 | 1 | 1 |
| `/analyses` | 1 | 1 | 1 |
| `/catalog/reports` | 1 | 6 | 1 |

공통 원인은 사이드바 크기 조절 버튼의 ARIA 역할, 즐겨찾기 버튼의 표시명·접근 가능한 이름 불일치, 텍스트·상태 배지 색 대비다. 기존 위반을 수정할 때 기준선 수도 함께 낮춰 재발을 차단한다.
