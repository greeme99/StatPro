# StatPro 테스트 결과 보고서 V1.0

## 1. 테스트 개요

- 수행일: 2026-10-25
- 환경: Windows, Python 3.12, Node.js 24.19, Chrome
- 범위: React 로컬 UI, 로컬 REST API, 원자적 Document Store, Dataset/Worksheet, ResultBundle JSON Schema, FMEA 7단계/revision/workflow, I-MR, Xbar-R, p/np/c/u, 정규 공정능력, 2수준 완전요인·정규 일부요인·Plackett–Burman 설계·응답 분석과 3–5요인 Box–Behnken·중심합성 반응표면 DOE, 균형 교차 Gage R&R, 입력 검증, JSON CLI
- 기준 출처:
  - NIST/SEMATECH Individuals Control Charts
  - NIST/SEMATECH Shewhart Xbar and R Control Charts
  - NIST/SEMATECH Attributes Control Charts
  - NIST/SEMATECH Western Electric 및 추세 규칙
  - NIST/SEMATECH 및 Minitab 공개 Plackett–Burman 설계표·구성 설명
  - NIST/SEMATECH Box–Behnken 3요인 설계표와 반응표면 설계 비교표
  - AIAG 및 VDA QMC 공개 자료의 FMEA 7단계 명칭과 순서

## 4. 발견 및 처리

NIST 페이지는 평균 이동범위를 1.8778로 표시한 뒤 한계를 계산해 UCL 55.8041, LCL 45.8159로 제시한다. StatPro는 중간값 1.877777…을 반올림하지 않으므로 내부 결과가 약 0.000012 다르다. 계산 정밀도를 유지하고 테스트는 NIST의 공개 표시 정밀도인 소수 4자리에서 비교하도록 수정했다.

정규 공정능력은 연속 관측값의 평균이동범위로 추정한 short-term sigma를 Cp/Cpk에, 전체 표본 표준편차를 Pp/Ppk에 사용한다. 두 추정치는 결과 모델에서 분리되며 안정성·정규성은 자동으로 확인된 것으로 표시하지 않는다.

DOE 생성기는 NIST 표준순서를 식별자로 보존하면서 별도의 재현 가능한 run order를 만든다. 5개 이상 요인은 완전요인 실행 수가 빠르게 증가하므로 fractional/screening design 검토 경고를 반환한다.

정규 2수준 일부요인 생성기는 사용자가 지정한 양의 생성식에서 기본 요인 열을 곱해 생성 요인을 만들고, 생성 단어의 모든 조합을 대칭차로 닫아 완전한 정의관계를 계산한다. 최단 비항등 단어 길이를 해상도로, 관심 효과와 각 정의 단어의 대칭차를 별칭 집합으로 반환한다. 해상도 III 설계에는 모든 요인 부호를 반전한 full mirror-image foldover를 추가할 수 있고, 원본/foldover phase를 각 실행에 보존한다. center point·block·음의 fraction·부분 foldover는 아직 포함하지 않는다. `Mtb14Book.dll`의 `CmDOEFactor::mGetGenerator`와 206개 `CmDOE*` 이름은 Minitab 14 기능 존재 후보만 뒷받침하고 계산식·기본값·런타임 동등성을 증명하지 않는다.

부분요인 응답 분석은 coded 직교 열에서 주효과 별칭 사슬당 대표항 하나만 적합한다. 원 설계에서는 전체 별칭 집합을 결과에 붙여 개별 원인으로 오해하지 않게 하고, 해상도 III full foldover 후에는 원 정의관계와 짝수 길이 정의 단어로 구성된 증강 정의관계를 함께 보존해 주효과가 2요인 교호작용과 분리됐지만 고차 별칭은 남을 수 있음을 표시한다. 잔차 자유도가 있으면 모형 잔차를, 포화 주효과 모형이면 Lenth PSE를 사용하며 반복이 없는 모형 잔차는 순수오차가 아니라는 경고를 보존한다. 잔차분산이 정확히 0이면 독립 오차 추정 없이 p값을 0으로 가장하지 않고 추론 불가로 표시한다. full foldover가 2요인 교호작용끼리의 모든 별칭을 해소한다고 주장하지 않는다.

중심합성계획(CCD)은 2~6개 정량 요인에 대해 완전요인점, 축점, 중심점을 생성한다. 회전가능형은 공개 NIST 정의에 따라 완전요인 실행 수의 4제곱근으로 alpha를 계산하고, 면중심형은 alpha=1을 사용한다. 분석은 coded 단위의 선형항·모든 2요인 교호작용·제곱항을 포함하는 완전 2차 모형을 OLS로 적합하고, ANOVA·순수오차·적합성결여·잔차를 보고한다. 잔차분산이 정확히 0이면 독립 오차 추정이 없으므로 표준오차와 p값을 추론 불가로 보존한다. 회전가능형 축점은 입력한 low/high 요인 범위를 벗어날 수 있으며, low/high가 안전 한계가 아니라 요인 큐브임을 경고한다. Minitab 14의 `CmCmndDOECCDesign`, `DOECreateCCDesign.cpp`, `CmDOERsPlot` 문자열은 기능 존재 후보를 뒷받침하는 정적 관찰일 뿐, 계산식·기본값·실행 동등성의 근거로 사용하지 않는다.

응답표면 탐색은 fitted quadratic를 `y=b0+b'x+x'Bx`로 구성하고 `x*=-0.5 B^-1b`의 정상점을 계산한다. canonical 고유값이 모두 음수면 최대점, 모두 양수면 최소점, 부호가 섞이면 안장점, 0에 가까운 방향이 있으면 능선/평탄으로 분류한다. 선택한 두 요인은 coded `[-1,1]`의 홀수 5–51 격자에서 평가하고 나머지 요인은 명시된 hold 값(기본 0)에 고정한다. 특이 행렬은 고유 정상점 없음으로, factorial cube 밖 정상점은 외삽으로 보존한다. 이는 NIST 공개 수학의 독립 구현이며 Minitab 14의 허용오차·기본 hold 값·contour 보간·색상·명령 문법과 동등함을 주장하지 않는다.

등고선은 bounded regular grid의 응답 최소·최대 사이에 1–12개 내부 수준을 놓고 marching-squares 선형 보간으로 iso-response 선분을 생성한다. 애매한 saddle cell은 cell-center 값을 이용해 결정론적으로 연결하며 coded/actual endpoint를 모두 보존한다. SVG는 디자인 토큰을 사용하고 동일 선분을 표로 제공한다. 이 알고리즘과 수준 선택은 StatPro 설계이며 Minitab 14의 contour topology, smoothing, 색상 또는 수준 기본값을 복제한 것이 아니다.

3D 응답표면은 동일한 bounded regular grid를 응답 최소·최대로 정규화하고 두 coded 요인과 응답 높이를 결정론적 등각 투영으로 변환한 SVG 와이어프레임이다. 시각화의 최소·최대 응답을 접근성 이름에 포함하고 원본 격자 표를 대체 데이터로 유지한다. 카메라 각도, mesh 밀도, 선 스타일은 StatPro UI 설계이며 Minitab 14 그래픽 엔진의 투영·조명·회전 동작을 복제한 것이 아니다.

Box–Behnken 생성기는 3–5개 정량 요인의 모든 요인쌍에 대해 두 요인만 coded ±1로 변화시키고 나머지는 0에 고정하는 4점 edge block을 구성한다. 자동 중심점 3/3/6개를 더해 공개 NIST 실행 수 15/27/46과 일치하며, 모든 cube corner를 제외한다. 실행순서 응답 분석은 중앙합성설계와 공유하는 단일 complete-quadratic 적합 경계에서 계수·ANOVA·순수오차/적합결여·잔차·R²를 계산한다. `mtb14.exe` 원본의 오프셋 7,646,980에서 `CmProjManBoxBehnken` 문자열을 관찰했지만 이는 기능 존재 후보일 뿐 Minitab 14의 설계표·기본값·명령·분석 출력·런타임 동등성을 증명하지 않는다. 상세 근거와 미확인 범위는 `docs/evidence/2026-10-25-box-behnken.md`에 보존했다.

Plackett–Burman 생성기는 공개된 12/20/24/32/36/44/48회 부호열의 순환 구성, 28회 9행·3블록 특수 구성, 20회 Hadamard 설계를 두 배로 확장한 40회 구성을 독립 구현했다. 반환 전 전체 기본 행렬의 열 균형과 모든 열쌍 직교를 검사하며, 8·16회는 공개 제품 설명과 같이 동일하거나 더 나은 2수준 요인설계 사용을 안내한다. 이는 공개 수학 설계의 재구성이며 Minitab 14 내부 알고리즘·표준순서·UI 동등성을 주장하지 않는다. `Mtb14Book.dll` 문자열·프로시저 이름 검색에서는 직접 일치가 관찰되지 않았고, `mtb14.exe` 검색은 Ghidra 공급자 무응답으로 결과를 회수하지 못했으므로 미확인 상태로 남긴다.

Plackett–Burman 응답 분석은 coded 열의 직교 최소제곱 주효과를 계산한다. 잔차 자유도가 있으면 잔차 평균제곱으로 효과를 표준화하고, 포화 주효과 모형이면 공개된 Lenth sparse-effects PSE와 margin-of-error 기준을 사용한다. Pareto는 절대 효과 또는 절대 표준화 효과를 순위화하며, 기준선을 넘은 요인은 인과 결론이 아니라 독립 확인실험 후보로만 반환한다. 중심점 평균 차이는 개별 이차항 검정이 아닌 기술적 aggregate curvature로 표시한다.

DOE 분석기는 생성된 실행순서와 응답을 일대일로 결합하고 coded ±1 최소제곱 모형으로 주효과와 선택한 차수의 상호작용을 계산한다. 반복된 설정은 Pure Error와 Lack of Fit을 분리하며, 포화 모형이나 잔차 자유도가 없는 경우 효과는 보존하되 F·p와 잔차 표준편차를 계산된 것으로 가장하지 않는다. 구현 근거는 NIST/SEMATECH의 공개 DOE 모형화·잔차 지침이며 Minitab 고유 계산이나 UI를 복제한 것이 아니다.

Minitab 정적 재검사에서는 `Mtb14Book.dll`에서 Predict 이름 22개와 Optim 이름 8개가 관찰되어 예측·최적화 기능 존재 후보를 보강했다. 이 이름 검색은 계산식이나 런타임 동작을 증명하지 않는다. StatPro는 NIST의 coded 수준 변환과 fitted prediction equation을 독립 구현했으며, 임의의 설계영역 내부 점을 예측하고 다중선형 2수준 모형의 모든 `2^k` 꼭짓점을 평가해 단일응답 최대·최소를 결정한다. 신뢰·예측구간은 아직 제공하지 않고 최적 설정은 확인 실험이 필요하다는 경고를 반환한다.

DOE 다중응답 최적화는 각 응답에 동일한 설계행과 coded 항 구조를 사용해 별도 모델을 적합하고, NIST가 공개한 Derringer-Suich 최대화·최소화·목표값 함수를 0–1 개별 desirability로 계산한다. 중요도는 가중 기하평균의 지수로 사용한다. 모든 꼭짓점과 중심점을 평가한 뒤 상위 시작점에서 결정론적 bounded pattern search를 수행하므로 목표값의 내부해를 찾을 수 있지만 전역 최적을 증명하지 않으며 확인 실험 경고를 보존한다. `Mtb14Book.dll`에서 `CmMROptStorage`, `mGetMROptimize`, 응답 수·시작점·스케일 관련 심볼이 정적으로 관찰됐으나 이는 Minitab 14의 다중응답 최적화 기능 존재 후보일 뿐 계산식·탐색 알고리즘·런타임 화면 동작을 증명하지 않는다.

I-MR 보조 규칙은 NIST가 공개한 Western Electric 4개 규칙과 6점 추세·14점 교대 규칙에 더해 공개된 Test 1–8 정의를 `nelson` 규칙 세트로 독립 구현했다. Xbar-R은 Xbar에 Test 1–8을, R에 문서상 지원 범위인 Test 1–4만 적용한다. 결과는 규칙 ID, 평가 창, 트리거와 관련 관측값 index를 함께 보존하며 `basic` 선택 시 3-sigma 이탈만 평가한다. 신호는 특별원인의 증명이 아니라 조사 후보이고 복수 규칙 사용은 오경보 빈도를 높인다는 경고를 반환한다. `Mtb14GraphicsCmnd.dll`의 관리도 관련 이름은 기능 후보만 뒷받침하며 Minitab 14의 규칙 계산식·기본 설정·현재 제품과의 동등성을 증명하지 않는다.

Gage R&R은 모든 작업자가 모든 부품을 같은 횟수로 측정한 균형 교차설계만 허용한다. 2원 랜덤효과 ANOVA의 method-of-moments 분산성분을 계산하며 음의 성분은 0으로 절단하되 진단에 원 추정값을 보존한다. ndc는 `floor(1.41 × part SD / Gage R&R SD)`이고 유한한 경우 최솟값은 1이다.

CSV Dataset은 원본 byte digest와 정규화된 타입 데이터 digest를 분리한다. 같은 내용과 가져오기 옵션은 파일 위치가 달라도 같은 Dataset digest를 가지며, Worksheet 편집은 부모 스냅샷을 변경하지 않고 새 revision과 parent digest를 생성한다.

Worksheet API와 UI는 업로드한 CSV bytes를 직접 파싱해 임시 파일 경로를 데이터 정체성으로 오인하지 않는다. 목록과 조회는 revision·storage version을 노출하고, 셀 편집은 `expected_storage_version`으로 오래된 화면의 덮어쓰기를 409로 차단한다.

FMEA는 통계 분석과 별도 bounded context로 분리했다. Study, Failure Analysis, Recommended Action, Risk Ratings, Audit Event의 소유권을 명시하고 모든 전이는 부모 digest를 가진 새 revision으로 생성한다. Action Priority는 고객이 적법하게 제공한 버전형 정책 매트릭스를 주입할 때만 계산하며 독점 판정표는 포함하지 않는다.

저장 seam은 동일한 3개 동작을 구현하는 메모리 adapter와 원자적 JSON 파일 adapter로 검증했다. 운영 adapter는 같은 디렉터리의 임시 파일을 flush/fsync한 뒤 replace하고, envelope 식별자와 ETag가 맞지 않는 소유 파일을 손상으로 처리한다. 현재 동시성 보장은 단일 프로세스 lock 범위다.

로컬 API는 Analysis Run 생성·조회·목록을 제공한다. Run ID는 불변이고 목록은 최대 100건 cursor paging이며, launcher는 loopback 이외 host를 거부한다. 검증 오류 응답에서는 원 입력값을 제거한다.

FMEA API는 기존 bounded context의 불변 revision을 저장 경계에 연결한다. 생성·목록·조회·고장분석 추가·검토요청을 제공하며, 모든 변경은 `expected_storage_version`으로 stale write를 409로 차단한다. UI는 적용 표준 버전과 revision을 함께 표시하고 외부 AP 정책이 없을 때 `미계산`을 명시한다.

FMEA 7단계 진행은 별도 가변 체크리스트를 저장하지 않는다. Planning and Preparation부터 Results Documentation까지의 상태·증거 수·남은 항목을 현재 Study의 고장분석, 권고조치, 상태와 감사 이벤트에서 결정론적으로 도출한다. 과거 저장 문서는 새 필드 없이도 읽을 수 있고 API 응답과 UI에서 같은 투영을 사용한다.

권고조치 API와 UI는 조치 ID·연결 고장분석·담당자·기한을 기록하고, 완료 시 실행 결과·증거 참조·재평가 S/O/D를 같은 immutable revision에 저장한다. 최초 위험은 유지되며 검토 중 Study는 미완료 조치가 없을 때만 승인된다.

Action Priority 정책은 사용자가 적법하게 제공한 S/O/D/우선순위 조합만 별도 불변 문서로 저장한다. 정책 key는 정규화된 내용 digest에서 도출하며, Study에는 lookup key와 digest를 함께 보존한다. 연결 시 표준 버전을 검사하고 기존 항목을 재평가하며, 이후 고장분석·조치 완료는 연결된 정확한 정책을 저장소에서 다시 검증한 뒤 사용한다. UI는 호환 정책만 선택지로 표시하고 독점 판정표를 기본 제공하지 않는다.

최초 Schema 검증에서 `ResultBundle.to_dict()`가 Python tuple을 SDK 소비자에게 그대로 노출하는 계약 불일치가 발견되었다. CLI JSON 직렬화에 의존하던 하위 보정을 제거하고 ResultBundle 소유 경계에서 assumptions/warnings를 JSON array로 정규화했다.

React 결과 화면의 최초 픽셀 검증에서 Recharts 자동 Y축이 관측값만 포함해 UCL/LCL을 잘라내는 결함을 발견했다. Y축 소유 경계에서 관측값과 양 관리한계를 함께 포함하도록 수정하고, 실제 기준선에 UCL/CL/LCL 라벨을 결합했으며 Y축 표시를 소수 두 자리로 제한했다.
