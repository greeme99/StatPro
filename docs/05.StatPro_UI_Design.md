# StatPro UI 디자인 시안 V1.2

## 1. 컨셉

제조 현장의 판단을 빠르게 만드는 데이터 중심 업무 화면이다. 장식보다 데이터, 상태, 원인과 다음 행동의 위계를 우선한다.

- 전역 `Work App Design System v1.0`을 변경 없이 상속한다.
- 브랜드 표면은 `--color-action`과 `--color-fill-brand`를 사용한다.
- 정상·주의·위험은 status semantic token과 텍스트/아이콘을 함께 사용한다.
- 요약 화면은 comfortable, 분석·테이블·FMEA는 compact density를 사용한다.
- 모든 UI 문구는 한국어로 쓰며, 현장 약어는 최초 노출에서 한글명과 병기한다.
- 상용 구독·업셀을 연상시키는 잠금, 크레딧, `Pro` 표시는 사용하지 않는다.

## 1.1 화면 역할

| 화면군 | 사용자의 질문 | 주된 표현 | 구현 원칙 |
|---|---|---|---|
| 홈 | 어떤 전문 작업공간 또는 개선 흐름을 시작할 것인가? | 핵심 전문 작업공간, 개선 프로젝트(DMAIC) | DOE·SPC·FMEA와 DMAIC 두 영역으로 시작점을 제공 |

| 분석 설정 | 실행할 준비가 되었는가? | 입력, 검증, 완료 조건 | 한 개의 primary action |

## 5.1 한국어 UI 표준 용어

화면에는 아래 **표준표현**을 사용하고, 괄호 안 표현은 코드·기술 문서 또는
외부 연동 맥락 외에는 사용자 화면에 노출하지 않는다.

| 표준표현 (비권장 표현) | 적용 범위 |
|---|---|
| 홈 (Dashboard) | 제품 첫 화면과 요약 현황 |
| 작업공간 (Workspace) | DOE·SPC·FMEA 업무 진입과 진행 화면 |
| 분석 실행 (Run) | 불변 Analysis Run 기록과 결과 식별 |
| FMEA 연구 (Study) | FMEA 개정·검토·승인 단위 |
| 관리계획서 (Control Plan) | PFMEA 연결 관리 항목 |
| 단계별 설정 (Guided workflow) | 순서형 분석 준비 흐름 |
| 빠른 설정 (Quick setup) | 숙련자를 위한 직접 입력 흐름 |
| 결과 및 보고서 (Results & Reports) | 실행 결과, 근거, 내보내기 |
| 사용하지 않음 (Unlock / Pro) | 상업형 잠금·업셀 문구 |

버튼은 동작을 명확히 표현한다. 예: `새 실험 만들기`, `실행표 생성`,
`분석 실행`, `보고서 내보내기`, `승인 검토 시작`.

## 5.2 DOE 작업공간 UX

- 상단은 경로, 실험명, 개정/상태, 도움말, 보고서 링크로 구성한다.
- 탭은 `설계 및 계획 → 실행 데이터 → 분석 → 결과 → 최적화 → 근거` 순으로
  유지한다. 아직 생성되지 않은 실행표 이후 탭은 잠그지 않고, 필요한 선행 조건을
  안내한다.
- 인자와 반응은 표로 편집한다. 각 표의 빈 상태는 각각 `인자 추가`, `반응 추가`라는
  단일 행동을 제공한다.
- 실행표 생성 전에는 예상 실행 수, 블록, 반복, 무작위화, 별칭 또는 해상도 경고를
  한 요약 패널에 보인다.
- 설계 유형 선택에는 현재 가능한 유형만 기본 목록에 둔다. 미구현 유형은 `개발 예정`
  표시를 가진 카탈로그 항목으로 분리한다.

## 5.3 구현 상태 표현

| 상태 | 의미 | UI 행동 |
|---|---|---|
| 구현됨 | 로컬 엔드투엔드 흐름 가능 | 기능으로 이동 |
| 개발 예정 | 실행 불가 | 안내 화면 + 대체 경로 |
| 외부 정책 필요 | 조직 정책/IdP가 필요 | 준비 항목과 책임 범위 안내 |

## 5.4 DOE 보고서 양식과 그래프 이미지

- DOE 결과 및 보고서 화면은 `보고서 양식` 선택과 HTML·그래프·CSV·JSON 묶음
  다운로드를 한 결과 영역에 둔다. 다운로드는 분석 실행을 변경하지 않는다.
- 양식은 `표준 분석 보고서`, `고객 검토용 보고서`, `규제 검토용 보고서`다. 후자의
  두 양식은 고객명/요구사항 또는 적용 규정/범위처럼 조직이 채워야 할 항목을 보여 줄
  뿐, 고객 승인·규제 준수·전자서명을 표시하지 않는다.
- 지원 가능한 ResultBundle plot은 HTML 인라인 SVG와 ZIP의 `charts/*.svg`로
  제공한다. 각 그래프에는 대체 텍스트와 원본 Plot 데이터 섹션이 함께 있다.

## 5.5 개선 프로젝트(DMAIC) 제안

- 대시보드의 전문 작업공간 아래에 `개선 프로젝트(DMAIC)`를 추가한다. 이 항목은
  통계 도구의 두 번째 메뉴 사본이 아니라 개선 프로젝트의 단계·근거 연결 허브다.
- 상단 단계 탭은 `정의 → 측정 → 분석 → 개선 → 관리` 순서를 고정하고, 좌측에는
  현재 단계와 도구 목록, 본문에는 단계 목표와 카드 목록을 배치한다.
- 카드의 상태는 `구현됨`, `개발 예정`, `외부 정책 필요`만 사용한다. `구현됨`은
  MSA/Gage R&R, 공정능력/SPC, DOE, FMEA 관리계획서의 기존 경로로 이동한다.
  원인분석·SIPOC·파일럿·품질 대시보드는 실행 버튼 없이 개발 예정 설명을 보인다.
- `DmaicProject`와 불변 `DmaicCharter`·`VoiceOfCustomerStudy`는 API 계약으로 구현되었다.
  프로젝트는 최신 문서의 ID·개정·digest만 보유하며, 문서 본문을 복제하지 않는다.
  SIPOC·문제 정의·이해관계자 분석은 다음 데이터 모델 증분이며, 기존 Analysis Run/FMEA Study는 계속
  ID·ETag·입력 digest로만 참조한다.

### 5.5.1 정의 단계: 프로젝트 헌장 중심 수직 증분

- 첫 수직 증분은 `프로젝트 헌장`이다. 열린 첫 패널에는 `프로젝트 제목*`, `프로젝트
  ID`, `프로젝트 책임자*`, `후원자`, `챔피언`, `부서`, `시작일`, `목표 종료일`을 둔다.
  날짜는 표준 날짜 입력을 사용하고, 사람·조직 이름은 인증·인사 시스템의 실제 권한을
  의미하지 않는 프로젝트 참조값으로 처리한다.
- 뒤따르는 접힌 패널은 `사업 타당성 및 문제 정의`, `프로젝트 범위`, `성공 지표`,
  `프로젝트 팀`, `자원 및 예산`, `DMAIC 이정표`, `이해관계자`, `위험 등록부`,
  `가정 및 제약조건`이다. 배지 숫자는 관련 항목 수이며 진행률·승인·준수의 증거가
  아니다.
- VOC는 API에서 수집 계획·데이터 지점·요구사항·불편·기회·조치·권고·다음 단계를 불변
  개정 문서로 보관한다. SIPOC, 문제 정의, 이해관계자 분석은 헌장 내부의 큰 폼을 복제하지 않고 별도
  연결 문서로 연다. 연결 화면은 프로젝트 ID와 현재 개정 digest를 명시하며, 최신본이
  아닌 연결은 경고한다.
- VOC 화면은 수집계획·데이터 지점·요구사항·불편·기회·조치·권고·다음 단계를, SIPOC는
  공정 경계와 공급자/입력/공정/출력/고객 목록을, 문제 정의는 영향·격차·기간/범위·
  심각도/긴급도를, 이해관계자 분석은 영향력·관심도·태도·소통 계획·우려·기대를
  다룬다. 화면에서 제공된 샘플·Word 내보내기는 아직 `개발 예정`이며 구현 상태를
  모방하는 비활성 버튼으로 표시하지 않는다.

### 5.5.2 측정 단계: 데이터 수집 계획과 분석 실행 연결

- `데이터 수집 계획`은 핵심 지표·기준값·목표값, 문제/목표 정의 연결, 수집 전략,
  표본추출 계획, 측정 시스템, 수집 양식, 수집자, 품질보증 절차, 분석 방법, 비용과
  보고 형식을 기록하는 별도 연결 문서다.
- 수집 전략은 `수집 방법`, `수집 주기`, `수집 시작일`, `수집 종료일`, `데이터 원천`을,
  표본추출 계획은 `표본추출 방법`, `모집단 크기`, `표본 크기`, `오차한계`, `신뢰수준`,
  `표본추출 근거`를 둔다. 숫자 입력의 기본값은 통계적 적합성 또는 승인 상태를 뜻하지
  않으며, 비어 있는 필수값은 저장 전에 명확히 검증한다.
- 측정 시스템은 `측정기`, `측정 단위`, `측정 정밀도`, `교정 계획`, `교정 필요`,
  `MSA 필요`를 기록한다. Gage R&R·공정능력·SPC 카드는 새 계산기를 만들지 않고
  해당 구현 화면으로 이동하며, 완료된 Analysis Run ID·ETag·input digest만 계획
  개정본에 참조로 저장한다.
- 수집 양식·수집자·품질보증 절차·분석 방법은 반복 행으로 관리한다. 빈 목록은
  `아직 등록되지 않음` 빈 상태를 보이며, “추가” 버튼은 행 편집기만 연다. Word/PDF
  출력과 외부 프로젝트 열기/저장은 실제 구현 전 `개발 예정` 안내로 제공한다.

### 5.5.3 분석 단계: 근본원인과 분석 방법 선택

- 근본원인 분석은 `설정 → 잠재 원인 → 근본원인 → 시정조치 → 결론`의 단계 rail을
  사용한다. 문제·영향·범위·목표는 Define 문서를 참조할 수 있지만, 사용자가 참조를
  선택하지 않았으면 빈 입력으로 남긴다.
- 특성요인도(이시카와), 5 Why, 일반 파레토는 각각의 revision 문서다. 원인 목록,
  질문 답변, 빈도/비용 데이터는 추정된 사실이 아니라 사용자 입력 또는 연결된 데이터
  원천으로 표시한다.
- 분석 방법 선택은 `질문`, `결과 변수 척도`, `그룹/짝지음/반복측정`, `공변량`,
  `예측 목적`을 기준으로 카드 목록을 좁힌다. 현 엔진에 없는 상관·회귀·t 검정·ANOVA·
  비모수·시계열·일반 파레토는 `개발 예정`으로 표시하고 실행 링크를 만들지 않는다.
- 카드에는 목적·입력 전제·결과 종류·제한을 함께 표기한다. DOE 효과 파레토는 DOE
  결과 안에서만 표시하며 일반 결함/원인 파레토와 같은 카드나 내보내기를 공유하지 않는다.

### 5.5.4 개선 단계: DOE 연결과 의사결정 문서

- 개선안 선정 매트릭스는 평가 기준/가중치, 개선안, 점수, 근거, 선정 사유를 각각
  접근 가능한 표와 편집 행으로 보여 준다. 가중치 합계와 점수 범위는 저장 전에
  검증하고, 계산된 순위에는 입력 가정과 동점 처리 방식을 함께 표시한다.
- 파일럿 계획은 파일럿 유형, 대상 범위, 설계, 표본 계획, 기간, 성공 지표, 중단 기준,
  위험 대응으로 구성한다. 비용편익 분석은 통화·분석 기간·비용/편익·가정·시나리오와
  계산된 지표를, 실행계획은 전략·단계·소통·품질·교육·완료 조건을 기록한다.
- DOE 실행, 파일럿 결과, 비용 추정, 담당자/교육 상태는 각기 다른 근거다. 화면은
  근거의 ID·ETag·digest와 미확정 상태를 표시하며, 권한·승인·재무 보증을 추정하지 않는다.

### 5.5.5 관리 단계: 지속 관리와 기존 분석 연결

- 관리 화면은 `관리 항목`, `모니터링 계획`, `반응 계획`, `검토 일정`을 편집하는
  DmaicControlHandoff와 기존 FMEA 관리계획서·SPC·공정능력 실행을 구분한다. 기존
  `ControlPlan`은 FMEA 연구가 소유하므로 이 화면에서 복제·수정하지 않고 식별자와
  개정 digest를 참조한다.
- 품질 지표는 지표명·단위·목표·경고 기준·담당자 참조·데이터 원천 계약·마지막 갱신 시각을
  함께 표시한다. 데이터 원천이나 갱신 주기가 없으면 실시간/최신 상태처럼 보이지 않게
  빈 상태와 누락 사유를 표시한다.
- 품질 관리 대시보드와 일반 결함 분석은 현재 `개발 예정`이다. SPC 결과는 공통
  `관리도 종류 선택 → 데이터 입력·검증 → 분석 결과 표시 → 결과 출력` 흐름으로만
  실행하며, 대시보드가 이를 대체하거나 별도 통계 결과를 생성하지 않는다.
